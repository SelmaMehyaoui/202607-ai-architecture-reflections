Observed facts and bounded meaning

What this run supports - and what it does not.

Directly observed

  • All three configurations returned the same correct summary.
  • Local MCP was fastest end to end in this set.
  • Isolated MCP used the fewest complete-system tokens.
  • Both MCP actions received automatic guardian review.
  • The isolated zero-argument contract required no model-generated paths.
  • The isolated server ran with constrained mounts and no network.

Bounded interpretation

  • A well-defined action interface can support correct model-mediated execution.
  • Context representation and action orchestration affected token use.
  • Isolation added little total time relative to Skill in this one run.
  • Supporting policy models can materially affect cost and latency.
  • The result is compatible with the translational-layer hypothesis.
  • It does not prove general superiority of MCP, Skills, or one boundary.

Validity limits

A first comparison set, not a benchmark distribution.

  1. There is one observation per configuration. No median, p95, uncertainty interval, or stable speed ranking can be inferred.
  2. Session position was Skill, local MCP, then isolated MCP. Cache and temporal effects may remain despite fresh threads.
  3. The interfaces differ by design: Skill text and terminal actions, a two-path local schema, and a zero-argument isolated schema.
  4. Guardian behavior is part of this Codex configuration and may change with product version, policy, or tool classification.
  5. Token counts come from local Codex rollout events. Cached tokens are included in input and total counts.
  6. Tool timing fields have different boundaries. Business logic, server duration, MCP invocation, action round trip, and end-to-end time must not be conflated.
  7. The experiment tests one deterministic CSV task on one host with one model and reasoning setting.
  8. Cross-model or general architecture claims require repeated, pinned comparison sets.

Glossary

Click a term to see its meaning.

These definitions use the meaning intended in this experiment. They are deliberately written for readers without a software, AI, or hardware background.

Codex

OpenAI's AI coding agent, tested here. Codex combines a language model with an application runtime that can read instructions, choose tools, request actions, receive results, and answer the user. The model proposes; the surrounding runtime performs the actual computer operation.

Model and reasoning setting

A model is the trained mathematical system that processes text and predicts a response or action. The reasoning setting controls how much internal computation the agent may use. Every run here used the displayed model GPT-5.6 Sol with Light reasoning.

Skill and SKILL.md

A Skill is a reusable set of written instructions, usually stored in a file named SKILL.md. It tells the agent when and how to perform a task. It does not execute code or grant permissions by itself. In this run, Codex followed the Skill and the agent runtime launched its declared Python script.

Script and Python process

A script is a file containing instructions for a computer. Python is the programming language used here. A process is a running instance of a program. Starting the Skill path created a Python process that read the CSV and wrote JSON.

MCP

Model Context Protocol is a standard way for an AI application to discover and call external tools. MCP describes the tool name, purpose, accepted arguments, and returned result. It does not automatically make a tool safe or isolated; deployment configuration determines its real authority.

Local MCP server

An MCP server running directly on the same Mac and under the same operating-system user as the client. It is a separate process, but that process boundary alone does not necessarily reduce filesystem, environment, or network permissions.

Isolated MCP server

The same kind of MCP tool run inside a deliberately restricted container. This experiment gave it one read-only input mount, one writable output mount, no network, a read-only root filesystem, a non-root user, and CPU and memory limits.

Tool, tool call, and tool schema

A tool is an operation made available to the agent. A tool call is the agent's structured request to use it. A schema is the machine- readable description of allowed arguments. The local MCP tool accepted two paths; the isolated tool accepted no arguments because its paths were fixed by container mounts.

stdio transport

Standard input and standard output are basic streams used by programs to exchange text or bytes. In this experiment, the Codex MCP client and each MCP server exchanged protocol messages through these streams instead of through a public network port.

Container

A container is a restricted environment for running a process with selected files, resources, and network access. It shares the host operating-system kernel, so it is lighter than a full virtual machine. Isolation comes from the container's actual settings, not from the word "container."

Colima

A tool that provides a Linux virtual machine on macOS for running containers. Docker-compatible commands were used to start the isolated MCP container through Colima.

Mount, read-only, and writable

A mount makes a selected host folder visible inside a container. Read-only means the process may read but not change it. Writable means changes are allowed. The isolated server could read only the input mount and write only to its dedicated output mount.

Root and non-root user

Root is the most privileged user inside a Unix-like environment. Running as non-root reduces what a compromised or faulty process can change. The isolated server ran as user ID 10001 rather than root.

CPU and memory limits

CPU is the hardware that performs instructions. Memory, or RAM, temporarily holds working data. The isolated container was limited to half of one CPU core and 128 MiB of memory to bound its resource use.

Deterministic operation

An operation designed to return the same output whenever it receives the same valid input. The order-summary calculation is deterministic, which lets the experiment compare architectures without ambiguity about the correct business result.

CSV and JSON

CSV is a simple table format in which values are separated by commas. JSON is a structured text format using named fields, lists, numbers, and strings. The experiment reads orders from CSV and writes the summary as JSON.

Token

A token is a small unit of text processed by a language model. A token may be a whole word, part of a word, punctuation, or formatting. Token counts describe model input and output volume, not MCP message count and not elapsed time.

Input, output, cached, and reasoning tokens

Input tokens are supplied to the model. Output tokens are generated by it. Cached input tokens are repeated input that the platform can reuse more efficiently; they remain included in the reported input and total counts. Reasoning tokens represent model computation reported within the output accounting.

Complete-system tokens

The sum of tokens used by every measured model involved in the task, not just the visible Codex agent. For MCP runs here, this equals the main-agent tokens plus the automatic guardian tokens. It prevents a supporting model's cost from disappearing from the comparison.

Guardian or supporting model

An additional model that reviewed whether an MCP action should be allowed. It returned an allow decision without showing a permission dialog to the user. Its latency and tokens are part of the complete system even though it is not the main conversational agent.

End-to-end duration

Total wall-clock time from submitting the controlled task until the final answer completed. It can include model inference, tool search, policy review, process or container work, data transfer, and response generation.

Time to first token

The delay between starting the task and receiving the first visible piece of model output. It measures initial responsiveness, not total completion speed.

Business, server, invocation, and round-trip time

Business-logic time covers the order calculation. Server duration includes the server's wrapper around that calculation. Tool invocation time covers the measured MCP invocation. Action round trip covers the agent's request until its result and may include guardian review. These boundaries are different and must not be compared as if they measured the same interval.

Cold start

A first execution that must initialize components such as a process, interpreter, MCP session, container, or model context. Cold results often include startup work that later calls can reuse.

Warm execution: three different meanings

"Warm" must name what is reused. A warm MCP server keeps the same server process and session alive. Warm operating-system caches reuse recently accessed files or program data even when a new process is started. Warm model or prompt caching reuses previously processed input tokens. These are separate effects and this report does not treat them as interchangeable.

Fresh Codex session

A new conversation with no result or discussion imported from a previous condition. Fresh sessions reduce cross-condition leakage, although shared software, model infrastructure, and system caches may still be warm.

SHA-256 and checksum

SHA-256 calculates a long digital fingerprint for a file. Matching fingerprints provide strong evidence that two files contain exactly the same bytes. A checksum manifest lists expected fingerprints so published evidence can be checked for accidental changes.

Observation, sample size, median, and p95

An observation is one recorded run. Sample size is the number of observations. A median is the middle value after sorting many runs. A p95 is a value at or above roughly 95 percent of observations. This report has one observation per condition, so it cannot provide meaningful medians, p95 values, or uncertainty estimates.
